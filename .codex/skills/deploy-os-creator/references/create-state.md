# Создание приватного состояния

Подтвердить владельца, локальный путь, приватный remote, первый реальный
потребитель и границы изменений live-систем. Восстановить существующий vault,
если найден его авторитетный источник. При отсутствии доступа к live закончить
локальную часть и перечислить точные отсутствующие входы.

В новом приватном Git-репозитории определить:

| Путь | Владение |
| --- | --- |
| AGENTS.md | Полномочия, секреты и критерий завершения |
| docs/architecture.md | Владельцы фактов и инварианты |
| docs/projects.md | Стабильные project_id |
| docs/inventory.md | Наблюдаемые хосты, сервисы, маршруты |
| docs/runbook.md | Inspect, backup, deploy, smoke, rollback, restore |
| projects/<id>/ | Профиль реального потребителя |
| catalog.toml, vault/ | Каталог и зашифрованные копии реальных секретов |
| recovery/ | Зашифрованные материалы независимого восстановления |

Создавать контуры по первому реальному потребителю. В `.gitignore` исключить
.env, открытые ключи, plaintext, runtime, временные файлы и локальные backups.
Установить проверенный toolkit в отдельный prefix по full commit, записать
origin и revision в приватный журнал. Задать `DEPLOY_OS_ROOT` новым checkout.
Общие команды остаются в toolkit; проектные операции находятся в private state.

Маркер приложения: `project=<id>` и `contract_version=1`. Plan не меняет хост.
Профиль должен уметь inspect, backup, deploy, smoke и rollback. Артефакт
связывается с commit управляемого репозитория и immutable digest.

Для реального секрета создать primary и независимый recovery age identity.
Значения ввести защищённым каналом; получателей сохранить в private SOPS config.
`catalog.toml` использует schema_version=1, секции projects, secrets, replicas,
mirrors; пример схемы — `examples/state/catalog.toml`. Регистрация реплики
предшествует import. `validate`, dry-run, import, check, sync и restore
проверяются без вывода значений. Замена authority требует явного источника.

Проверить два независимых способа восстановить Git и расшифровать контрольный
контейнер. Задать scope backup данных, RPO/RTO и rehearsal restore. Проверить
bundle и каждый обязательный mirror на ожидаемый commit и политику доступа.

Документировать локальные проверки и live-приёмку отдельно. Чистая локальная
среда должна разрешить project_id, выполнить plan и восстановить синтетические
данные. Рабочая приёмка требует разрешённого smoke фактического потребителя.
